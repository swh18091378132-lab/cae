## What to build

优化循环的核心，**纯算法**，不跑 Study、不碰 DB。这样单测可以秒级完成、且能用解析可算的假目标
验证搜索逻辑本身对不对。

新建 `core/optimizer.py`：

- **核心入口只接受一个注入的 `evaluate(设计向量) -> 评估结果` 回调**。优化器不知道 Study、
  不知道 Abaqus，只知道"给我一个向量，我告诉你结果"。
- **DOE 采样**：连续变量按范围铺点，离散变量按候选值/整数步长取点。
  要有确定性（同配置同种子同结果），否则无法回归。
- **约束筛选**：在可行点里挑目标最优（最小化）。**没有可行点时要明确报告**，
  不能返回 `None` 就说"优化完成"。
- **收敛判定**：可配置的"最大评估次数 + 最大轮数 + 改进量阈值"三元组，达到任一上限即停，
  并给出**停止原因**（`max_evals` / `max_rounds` / `converged` / `no_feasible`）。
- **不假设目标可微**：FI/MS 来自离散求解，不是光滑函数。离散变量做**邻域搜索**，
  连续变量做**步长收缩**，不做梯度下降。
- **去重与缓存**：重复的设计点不重复评估（撞点很常见，尤其离散变量）。
- **技术故障不算作"目标很差"**：`ok=False` 的点要单独归类，绝不能进入"最优"比较。
- **可中断可续跑**：已评估的点能被导出/导入，中途停机不必从头再来。

## Acceptance criteria

- [ ] 核心入口只依赖注入的 `evaluate` 回调（单测完全不跑 Study，秒级完成）
- [ ] 同配置同种子 → 同结果（确定性可回归）
- [ ] DOE 采样覆盖范围正确：连续变量落在范围内、离散变量取合法值
- [ ] 在约束下选出目标最优的可行点；断言选中的确实是可行点里最优的
- [ ] 完全没有可行点时明确报告（有可读原因），不返回含义不明的 None
- [ ] 收敛/预算三种停止原因各自可达且被正确报出
- [ ] **不使用梯度下降**：对非光滑目标（阶梯状）仍能稳定改进
- [ ] 重复设计点不重复调用 `evaluate`（断言调用次数）
- [ ] 技术故障的点不参与"最优"比较（构造一个 ok=False 但目标值极小的点，断言它不会被选中）
- [ ] 已评估点可导出/导入，续跑不丢也不必重算
- [ ] 纯算法，无第三方依赖，Python 3.8 兼容
