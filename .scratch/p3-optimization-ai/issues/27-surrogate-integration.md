## What to build

把 #24 的代理模型接进 #25 的优化循环，作为**可选**的快筛手段：
在决定"下一轮算哪些点"之前，先用代理模型给候选排序，优先评估预测更好的点。

核心约束（ADR-0002）：**代理模型只影响"先算哪个"，不影响"算出来算不算合格"**。
且它必须能被关掉 —— 数据不够或算力不足时，闭环退化为纯确定性 DOE + 邻域搜索，
行为与 #25 完全一致。

- 优化过程中累积已评估点 → 达到最小样本数后尝试拟合 → 误差达标才启用排序
- 误差不达标就**自动降级为不排序**，并在汇总里说明原因（不静默）
- 汇总里必须能区分"这个点是代理模型建议先算的"与"这个点是确定性搜索到的"
- 关掉快筛时，用**同一预算**跑出的轨迹应与纯确定性路径一致（可断言）

## Acceptance criteria

- [ ] 代理模型作为**可选开关**暴露，默认关闭时闭环行为与 #25 一致
- [ ] 累积到最少样本数后自动启用；样本不足时明确不启用并说明
- [ ] 误差不达标时自动降级为不排序，原因在汇总中可见
- [ ] 汇总能区分「代理模型建议」与「确定性搜索」来源
- [ ] **代理模型绝不改变任一设计点的合格判定**（断言合格与否只取决于实际校核结果）
- [ ] 启用快筛不改变"最终最优点必须是实测可行点"这条性质
- [ ] Python 3.8 兼容
