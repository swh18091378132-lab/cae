# P1 端到端闭环：机翼盒段 参数化建模 → CAE → 结果提取 → 强度校核 → 报告

Status: ready-for-agent
Type: spec
Created: 2026-10-23

> 术语一律使用 `GLOSSARY.md` 定义（自然格、参数化数模、层合板/铺层、失效指数 FI、安全裕度 MS、强度校核、危险部位、可追溯性、分析任务 Study、参数集、结构拓扑模型、血缘、参数契约、参数化包络）。
> 遵循 ADR-0001~0011，尤其是 ADR-0003（Abaqus Python 2.6.2）、ADR-0005（铺层作 CAE 属性）、ADR-0006（结果中间格式）、ADR-0007（强度校核为确定性引擎）、ADR-0008（自然格一等公民）、ADR-0010（网格与拓扑对齐）。

## Problem Statement

结构设计工程师目前机翼盒段这类复合材料部件的"建模—分析—校核—出报告"流程是割裂的：几何在 CATIA 里手工建、有限元在 Abaqus 里单独跑、结果靠人工看云图找危险部位、强度校核用 Excel 手算、报告靠人工拼。这个流程有三个痛点：

1. **不可追溯**：改了一个参数后重新建模求解，无法回答"这份报告到底对应哪一版数模、哪一版网格、哪套校核规则"。
2. **效率低且易错**：逐单元、逐铺层的强度校核靠人工几乎做不完；危险部位靠肉眼找，容易漏。
3. **无法迭代**：想改外形或铺层再算一轮，前面的东西全部重来，且新旧结果无法对比。

P1 的目标不是做全平台，而是**在一个部件（机翼盒段）上把整条链端到端跑通并全程可追溯**，证明这条路走得通。目标机为 Windows 7 64-bit，算力未知，必须按最小规模实现。

## Solution

交付一个本地工程工作台（Python 3.8 + Tkinter，单机、免部署），让单个工程师用一个 **Study（分析任务）** 承载一次完整的"参数集 → 参数化数模 → 结构拓扑/自然格 → 有限元模型 → 求解 → 结果抽取 → 强度校核 → 强度校核报告"过程：

- 用户填一组**参数集**，工作台驱动 CATIA 再生**参数化数模**，并自动生成**结构拓扑模型**与**自然格**。
- 工作台把数模抽象成有限元模型，调用 Abaqus 求解，抽取结果到中性中间文件。
- **确定性**强度校核引擎按用户规则逐单元、逐铺层计算 FI/MS，并按**自然格**聚合，标出**危险部位**。
- 按用户 `.docx` 模板生成**强度校核报告**。
- 全过程中每一步产物都是**不可变版本**，通过**血缘 DAG** 串起来，可完整回溯。

关键约束：分析、求解、校核的计算与判定全部是确定性（L0）；AI 只在已有结构化数据上做解释与草案（L1）；参数选型、规则确认、报告签发是人（L2）。P1 不引入 3DEXPERIENCE 铺层自动化（铺层作 CAE 属性），不建 Web 端。

## User Stories

1. 作为结构设计工程师，我想新建一个 Study 并命名，以便把一次分析的所有产物归到一起。
2. 作为结构设计工程师，我想输入一组具名参数（展长、后掠、弦长、肋数、桁条数等）作为参数集，以便驱动数模。
3. 作为结构设计工程师，我想让工作台校验参数是否落在模板的**参数化包络**内，以便在越界时立即阻止并提示。
4. 作为结构设计工程师，我想让工作台自动驱动 CATIA 按参数集再生**参数化数模**，以便不必手工改模型。
5. 作为结构设计工程师，我想在 CATIA 再生失败时看到可读的错误原因，以便定位是哪个参数/特征出的问题。
6. 作为结构设计工程师，我想让工作台从数模自动生成**结构拓扑模型**（长桁线 × 肋线），以便后续划分自然格。
7. 作为结构设计工程师，我想让工作台自动生成**自然格**并为每个格分配稳定 ID，以便逐格校核与出报告。
8. 作为结构设计工程师，我想让无法由四边长桁/肋围合的**不连续格**被显式标记（runout/开口/部分肋），以便知道哪里需要人工判断结构处理。
9. 作为结构设计工程师，我想让有限元网格沿长桁线/肋线切分、与自然格对齐，以便单元能唯一归属到自然格。
10. 作为强度分析工程师，我想把复合材料**铺层**（铺层顺序、角度、厚度、材料）定义为 FE 截面属性，以便改铺层时不必动几何。
11. 作为强度分析工程师，我想让工作台按模板生成有限元模型（几何抽象、网格、材料/铺层、载荷、边界），以便不必手写 inp。
12. 作为强度分析工程师，我想让工作台调用 Abaqus 运行指定的分析类型（P1 首批：静力、模态、屈曲），以便得到结果。
13. 作为强度分析工程师，我想让工作台把 Abaqus 的 ODB 结果抽取成 CSV/JSON + manifest，以便结果可被平台消费与追溯。
14. 作为强度分析工程师，我想让抽取文件记录来源 ODB 的指纹、section point 口径、单位，以便任何结果都能被复现。
15. 作为强度分析工程师，我想用声明式规则（YAML/JSON）指定每个材料/区域用哪种失效准则、许用值来源、安全系数、MS 阈值，以便校核规则可配置、可版本化。
16. 作为强度分析工程师，我想让校核引擎对每个单元 × 每个铺层 × 每种准则计算 FI 与 MS，以便不漏掉任何危险层。
17. 作为强度分析工程师，我想让每个单元取其最差铺层的结果，以便得到单元级判定。
18. 作为强度分析工程师，我想让结果按**自然格**聚合（取该格最差单元），以便按结构分区给出校核结论。
19. 作为强度分析工程师，我想让**危险部位**（FI 最大 / MS 最小）被自动定位，以便快速找到薄弱点。
20. 作为强度分析工程师，我想在有限元模型视图上看到危险部位的标注，以便直观核对。
21. 作为强度分析工程师，我想让不连续格被排除出自然格级校核但仍在单元级校核，以便既不误判又不漏检。
22. 作为强度分析工程师，我想按用户提供的 `.docx` 占位符模板生成报告，以便报告格式符合单位规范。
23. 作为强度分析工程师，我想报告里自动填入参数、模型信息、校核明细表、危险部位图与结论，以便不用手工拼。
24. 作为审核人员，我想看到报告对应的完整**血缘**（参数集→数模→网格→inp→odb→抽取→校核→报告各版本），以便确认报告可追溯。
25. 作为审核人员，我想在追溯链里看到每一步的指纹（哈希），以便识别产物是否被替换。
26. 作为审核人员，我想对"规则确认""报告签发"这类节点留下人类决策审计记录（谁、何时、依据），以便责任可追溯。
27. 作为结构设计工程师，我想在改参数后重跑同一个 Study 时**新增版本而非覆盖旧版本**，以便新旧结果可对比。
28. 作为结构设计工程师，我想列出所有 Study 并看到各自的产物数量，以便管理多个分析任务。
29. 作为结构设计工程师，我想让整条链能"一条命令/一个界面"跑完，以便验证端到端可行。
30. 作为结构设计工程师，我想在 P1 里不依赖 Web/浏览器也能用（Win7 上现代浏览器已不可靠），以便在目标机上直接工作。
31. 作为系统维护者，我想让所有 Abaqus 侧脚本用 Python 2.6.2 兼容语法并可静态检查，以便在 6.13 环境不炸。
32. 作为系统维护者，我想让平台宿主与 Abaqus 之间只交换 JSON/CSV 文本，以便跨解释器版本无耦合。
33. 作为系统维护者，我想让产物入库（SQLite）而 Abaqus 侧只吐文件，以便追溯与查询解耦。
34. 作为审核人员，我想知道哪些格是"不连续格"以及为什么（runout/开口/部分肋），以便推动结构处理决策。
35. 作为项目负责人，我想在一次成功跑通后得到一个可演示的最小闭环，以便向干系人证明方案可行。

## Implementation Decisions

### 模块（P1）

- **本地工作台（apps/workbench，Python 3.8 + Tkinter）**：UI 页（项目/参数/运行/结果/报告）+ 领域核心。
- **数据与追溯层**：SQLite（`db`）、Study 与血缘（`study`）。M0 已实现并自测通过：`studies` / `artifacts`（带 version、checksum、UNIQUE(study_id,kind,version)、**不可变触发器**）/ `edges`（DAG）/ `decisions`（L2 审计）。
- **CATIA 驱动（`catia_driver`）**：V5 Automation（win32com），读**参数契约**校验后 set 参数 → `Part.Update()` → 保存 CATPart 并记录哈希。真机用 win32com，测试注入 fake。
- **模板注册表（`template_registry`）**：每个结构族模板声明**参数契约**（参数名/类型/范围/几何映射）与**参数化包络**。
- **结构拓扑 / 自然格（`topology`）**：由长桁线 × 肋线在参数空间建拓扑再映射物理空间，生成自然格稳定 ID；对不连续格（runout/开口/部分肋）做连续性校验并标记。**已有原型 `prototype/natural-bay/gen_natural_bays.py` 验证过算法**，此模块是原型的工程化移植。
- **CAE 能力库（abaqus_capabilities，Abaqus 内置 Python 2.6.2 中运行）**：`geom_prep` / `mesh` / `material_layup` / `loads_bc` / `solve` / `extract` / `compat_check`。参数化函数 + 工作流配置。
- **结果中间层（`extract`）**：ODB → CSV/JSON + manifest（element × ply × 场量），manifest 记录来源 ODB 指纹、section point 口径、单位。
- **强度校核引擎（`strength_check`）**：读取抽取结果 + 声明式规则，遍历单元 × 铺层 × 准则计算 FI=施加/许用、MS=许用/施加−1；单元取最差铺层 → 自然格聚合取最差单元；输出明细 + 判定 + 危险部位列表。
- **报告（`report`）**：`python-docx` 灌数进 `.docx` 占位符模板（表、图、结论）。
- **Study 编排器（`run_study`）**：把上述串成一条链，维护血缘边，是**唯一主测试切口**。

### 接口契约（关键）

- `run_study(study_id, parameter_set, adapters)`：`adapters` 提供 `catia`（CatiaDriver 协议）与 `abaqus`（AbaqusRunner 协议）。返回本次 Study 的产物图与总结。测试用 fake 适配器即可确定性端到端。
- `CatiaDriver.regenerate(parameter_set, template_id) -> CatPartResult(path, checksum, topology_hint)`
- `AbaqusRunner.solve(fe_model, analysis) -> OdbResult(path, checksum)`；`AbaqusRunner.extract(odb, spec) -> ExtractionResult(csv/json/manifest)`
- `topology.build(parameter_set, template_id) -> TopologyModel(bays, discontinuities)`
- `strength_check.check(extraction, rules) -> CheckResult(detail_rows, cell_judgements, bay_judgements, hotspots)`

### 架构与追溯

- 一切产物进 `artifacts`，按 kind 版本递增、不可覆盖（M0 已实现触发器）。
- 血缘用 `edges` 表达；`run_study` 负责连边。
- L2 决策（规则确认、报告签发）进 `decisions`。
- Abaqus 与宿主仅文本交换（JSON/CSV），不传对象（ADR-0003/0006）。
- 网格必须与结构拓扑对齐，跨界单元不得作为交付网格（ADR-0010）。
- 铺层作 CAE 属性（ADR-0005），P1 不接 CATIA 复合材料模块。

## Testing Decisions

**好的测试只验证外部可观察行为，不测实现细节。** 断言"给定参数集，产出的自然格数量/不连续格标记/校核判定/血缘链"这类结果，而非内部函数调用顺序。

**主切口（已与用户确认）**：`run_study(...)` 编排器，注入 **fake `CatiaDriver` / `AbaqusRunner`**，确定性跑完整条 P1 链并验证：
- 血缘 DAG 完整（参数集→…→报告各节点存在且连边正确）；
- 产物不可变（重跑新增版本、旧版本内容不变）；
- 校核结果与不连续格处置符合 ADR-0007/0008/0010。

**两个纯算法直接单测**（不造新 seam，它们是纯函数式输入输出）：
- `topology.build`：用原型已验证的四类场景（干净/runout/开口/部分肋）作为回归用例——期望自然格数与不连续格标记与原型一致。
- `strength_check.check`：用手造的小规模抽取数据 + 规则，验证 FI/MS 计算、单元取最差铺层、自然格聚合、危险部位定位、边界情形（FI=1、MS=0）。

**先例（prior art）**：`apps/workbench/tests/test_m0.py` 已建立"纯标准库 + 临时库 + 断言外部行为"的测试风格，P1 其余测试沿用此风格并扩展为 `unittest`/等价结构。

**测试环境约束**：测试**不得依赖 CATIA/Abaqus 真机**（fake 适配器）；测试库文件写在仓库内 `.tmp_test/`（沙箱不允许写系统临时区，已在 M0 踩过）。目标机 Python 3.8，测试也须 3.8 兼容。

## Out of Scope

- Web 协作端、多角色审批流（P2）。
- 3DEXPERIENCE / V6 铺层几何自动化（ADR-0011，P2 门控 GATE-1）。
- Explicit 求解、非线性、接触（P2；P1 首批仅静力/模态/屈曲）。
- AI 增强（代理模型、LLM 解释、自动标注）（P3；P1 只保留接口位置不实现）。
- 尾翼/机身/全机总体装配（P2）。
- 大网格/大装配、并行/集群求解（算力未知，P1 按最小算例）。
- 铺层几何 / ply book / 可制造性（ADR-0005 明确不做）。
- 优化迭代闭环（P3）。
