# P2 部件族扩展：尾翼/机身/全机 + 多分析类型 + 网格质量优化 + 多角色审批流

Status: ready-for-agent
Type: spec
Created: 2026-10-23

> 术语一律使用 `GLOSSARY.md` 定义（自然格、参数化数模、层合板/铺层、失效指数 FI、安全裕度 MS、强度校核、危险部位、可追溯性、分析任务 Study、参数集、结构拓扑模型、血缘、参数契约、参数化包络）。
> 遵循 ADR-0001~0013，尤其 ADR-0002（AI 三层）、ADR-0005（铺层作 CAE 属性）、ADR-0007（确定性校核）、ADR-0008（自然格一等公民）、ADR-0010（网格与拓扑对齐）、ADR-0012（Abaqus Python 2.7）、ADR-0013（CATIA 无许可证现状）。
> P1 已完成并全部关闭（#1–#8），代码基线 `836ea9e`。

## Problem Statement

P1 证明了"单个机翼盒段从参数到强度校核报告的端到端闭环"可行，但它只覆盖了**一个部件、一种分析类型、一种网格策略、单人操作**。真实型号研发现有四个绕不过去的缺口：

1. **部件族不止机翼**：尾翼、机身筒段的结构拓扑与参数契约完全不同（机身有框、桁条、开口、对接面；尾翼有前后梁、翼肋、操纵面切口），P1 的机翼盒段模板无法复用，必须为每个族重建拓扑生成规则与模板参数契约。
2. **全机总体装配没人做**：真实型号要的是"全机总体参数（翼展、机身长、尾容量等）→ 各部件参数集 → 各部件分析 → 汇总"的层级关系，P1 的 Study 是扁平的，装不下这种层级。
3. **分析类型不够**：P1 只有静力/模态/屈曲，且都是线性的。真实复材结构要面对**接触、非线性、冲击/后屈曲（Explicit）**，而这些在 Abaqus 侧是完全不同的建模与提交方式。
4. **网格只能手工定**：P1 用固定 `subdiv_per_bay`，复杂几何下网格质量无法保证（畸变单元、长宽比过大），而这直接影响应力精度与自然格归属。

此外还有一条管理缺口：**P1 是单用户跑通，没有任何审批与权限概念**。而强度校核报告的签发在真实体系里必须有人签字负责（L2 决策门），不能由跑流程的人自己签。

## Solution

在 P1 的端到端闭环之上，横向扩展为**多部件族、多分析类型、可审批**的型号级分析平台：

- **部件族模板化**：机翼盒段、尾翼盒段、机身筒段、全机总体各有一套"模板 + 参数契约 + 参数化包络 + 拓扑生成规则"，用户选族即用，不必重写代码。
- **全机层级**：新增"型号配置"概念，把全机总体参数分解为各部件参数集，一次驱动多个部件 Study，并汇总各部件校核结论。
- **多分析类型**：在 `AbaqusRunner` 契约上扩展分析类型（静力/模态/屈曲之外，增加接触、非线性、Explicit），fake 与 real 同签名，保证 fake 可回归。
- **网格质量门**：网格生成后自动评估质量指标（畸变度、长宽比、翘曲），不达标的自然格给出提示并可自动加密，且**不破坏 ADR-0010 的拓扑对齐约束**。
- **多角色审批流**：设计、强度分析、审核、签发四种角色，报告必须经"审核→签发"两步才能成为最终版；所有决策记入 L2 审计日志（P1 已有 `decisions` 表）。

## User Stories

1. 作为结构设计工程师，我想从模板列表里选择"尾翼盒段"并填参数，得到一份参数化数模，以便不必为尾翼重写建模代码。
2. 作为结构设计工程师，我想让尾翼的参数契约包含前后梁位置、翼肋数、操纵面切口，以便尾翼的典型结构特征被正确表达。
3. 作为结构设计工程师，我想选择"机身筒段"模板并指定框位、桁条数、开口位置，以便机身筒段的加筋壳体被参数化建模。
4. 作为结构设计工程师，我想让机身筒段的自然格按"框×桁条"围合生成，以便机身也具备逐自然格校核能力。
5. 作为结构设计工程师，我想在全机总体层级输入翼展、机身长、尾容量等总体参数，以便一次确定各部件的主要参数。
6. 作为结构设计工程师，我想让平台按总体参数自动分解出机翼、尾翼、机身各自的参数集，以便不必手工逐部件填参。
7. 作为结构设计工程师，我想在一次操作里对全机三个部件分别跑通"建模→求解→校核"，以便得到型号级结论而不是单部件结论。
8. 作为结构设计工程师，我想看到全机汇总视图（各部件最大 FI、最小 MS、是否合格），以便快速判断全机强度状态。
9. 作为强度分析工程师，我想选择"接触分析"并指定接触对，以便分析部件间的接触传力。
10. 作为强度分析工程师，我想选择"非线性分析"并指定材料非线性或几何非线性，以便分析大变形问题。
11. 作为强度分析工程师，我想选择"Explicit 分析"并指定时间步与质量缩放，以便分析冲击与后屈曲。
12. 作为强度分析工程师，我想让不同分析类型产出同样格式的抽取结果，以便后续校核逻辑不需要区分分析类型。
13. 作为强度分析工程师，我想看到网格质量报告（每个自然格的畸变度、长宽比、翘曲度），以便知道哪里网格可能不可靠。
14. 作为强度分析工程师，我想让质量不达标的自然格被自动加密重划，以便在不人工干预的情况下改善网格。
15. 作为强度分析工程师，我想在网格加密后仍然保证单元唯一归属自然格，以便校核口径不变。
16. 作为强度分析工程师，我想在网格质量无法达标时收到明确警告并记录在案，以便报告中能体现这一局限。
17. 作为强度分析工程师，我想让不同部件族沿用同一套强度校核规则，以便型号内校核口径统一。
18. 作为强度分析工程师，我想为不同部件族指定不同的默认准则与许用值，以便贴合各族材料与结构特点。
19. 作为审核人员，我想看到待我审核的报告列表，以便知道有哪些报告需要处理。
20. 作为审核人员，我想在审核时看到报告对应的完整血缘与校核明细，以便判断结论是否可信。
21. 作为审核人员，我想对报告做出"通过/退回"决定并填写意见，以便责任可追溯。
22. 作为审核人员，我想看到报告被退回的原因，以便据此要求分析人员修正。
23. 作为签发人员，我想只有通过审核的报告才能进入签发环节，以便流程不能跳步。
24. 作为签发人员，我想签发后报告变为"最终版"且不可再修改，以便最终报告具备权威性。
25. 作为签发人员，我想看到签发记录（谁、何时、对哪一版报告），以便事后审计。
26. 作为项目负责人，我想看到每个 Study 当前处于流程的哪个环节（分析中/待审核/已签发），以便掌握进度。
27. 作为项目负责人，我想看到全机各部件的研究进度汇总，以便在型号层面掌握整体状态。
28. 作为结构设计工程师，我想在改参数后重跑，新版本报告需要重新走审批，以便旧审批不会错误地"继承"到新内容。
29. 作为结构设计工程师，我想在 X 部件改用新参数后，全机汇总自动更新，以便型号结论始终反映最新设计。
30. 作为系统维护者，我想让所有 Abaqus 侧脚本继续通过 Python 2.7 兼容检查，以便在 Abaqus 2023 上不炸。
31. 作为系统维护者，我想让新分析类型的 fake 适配器保持确定性，以便 CI 不依赖 Abaqus 许可证。
32. 作为系统维护者，我想让模型层级（全机→部件）在数据库中可表达，以便血缘能跨部件追溯。
33. 作为系统维护者，我想让已有 P1 的 Study 数据继续可用，以便升级不破坏历史数据。
34. 作为系统维护者，我想让 CATIA 不可用时降级到 fake 并有清晰提示，以便现场许可证问题不阻塞开发。
35. 作为审核人员，我想在报告中看到网格质量警告（若有），以便知道结论的适用边界。

## Implementation Decisions

### 复用 P1 主切口（已与用户确认）

P2 **不新增架构级测试切口**，沿用：

- **`run_study(...)`** —— 唯一主编排入口。P2 通过扩展其参数（分析类型、模板族、网格质量策略）而非新建入口。
- **`CatiaDriver` / `AbaqusRunner` 协议** —— 增加能力时扩展协议方法，fake 与 real 保持同签名。
- **`workbench_service`** —— 审批流等应用逻辑放这里（纯 Python，可测；P1 已验证此模式）。
- **纯算法模块直接单测** —— 网格质量评估属此类（P1 的 `topology` / `strength_check` 有先例）。

### 模块

- **模板族扩展**：新增尾翼盒段、机身筒段、全机总体的模板 JSON（参数契约 + 参数化包络）与对应的拓扑生成规则。
- **拓扑生成策略化**：`topology` 从"机翼盒段专用"抽象为"按模板声明的布置规则生成"，支持翼面类（长桁×肋）与筒段类（桁条×框）两种拓扑模式。
- **型号配置层**：新增"型号配置"概念，表达全机 → 各部件的层级与参数分解关系；部件 Study 通过引用型号配置关联起来。
- **分析类型扩展**：`AbaqusRunner.solve` 增加分析类型维度（静力/模态/屈曲/接触/非线性/Explicit），`fe_build` 按类型产出不同分析步与接触定义。
- **网格质量门**：`meshgen` 增加质量指标计算（畸变度、长宽比、翘曲）与局部加密策略，且**加密后仍满足每单元唯一归属一个自然格**（ADR-0010 不可破）。
- **审批流**：新增角色（设计/强度分析/审核/签发）与状态机（分析中 → 待审核 → 已签发 / 已退回），所有状态变更加 `decisions` 审计（P1 已有表）。

### 关键契约

- `run_study(...)` 增加：分析类型、网格质量策略（是否启用自动加密、阈值）、型号配置引用（可选）。
- `AbaqusRunner.solve(inp, job, work_dir, analysis=...)` —— `analysis` 描述分析类型与其参数（如 Explicit 的时间步、接触对）。
- 审批状态机：报告产物增加审批状态；**重跑产生新报告版本时，审批状态重置为"待审核"**（不得继承旧审批）。
- 型号配置的汇总查询返回各部件最新校核结论与流程状态。

### 数据库

- 新增型号配置与其部件关系（层级表达）。
- 报告/Study 增加审批状态字段。
- 其余沿用 P1 schema；**须保证 P1 已有数据可平滑升级**（新增列/表，不破坏既有结构）。

## Testing Decisions

**好的测试只验证外部可观察行为**：给定输入（模板、参数、分析类型、角色动作）断言输出（产物、血缘、状态、汇总结论），不断言内部函数调用顺序。

沿用 P1 的先例（`apps/workbench/tests/test_m*.py`：纯标准库、临时库、`main() -> int`、由 `run_tests.py` 统一调度）。

- **部件族**：每个新模板都用 `run_study` 跑通 fake 全链，断言产物齐全、自然格数量与拓扑规则一致、不连续格正确标记。
- **型号配置**：给定全机总体参数，断言分解出正确的部件参数集；多部件跑通后断言汇总视图数值正确。
- **分析类型**：fake 适配器对每种分析类型返回确定性结果；断言抽取结果格式一致（后续校核无需分支）。
- **网格质量**：纯算法单测——构造已知质量好/坏的网格，断言指标计算正确、加密后单元仍唯一归属自然格。
- **审批流**：service 层单测——断言状态机合法/非法转换、审计记录、**重跑后状态重置**。
- **Abaqus 侧脚本**：继续通过 `compat_check`（Python 2.7 基线）。
- **真机**：探测到 Abaqus 则跑；CATIA 依 ADR-0013 现状跳过并显式 SKIP 提示。

## Out of Scope

- 3DEXPERIENCE 铺层几何自动化（ADR-0011，须先完成 GATE-1 验证）。
- 代理模型、LLM 解释、自动标注（P3）。
- 优化迭代闭环（P3，ADR-0009）。
- Web 协作端（P1 已定 Win7 上不建；审批流先在本地工作台实现）。
- Explicit 之外的显式动力学高级功能（SPH、CEL、XFEM 等）。
- 真实型号的完整材料库与许用值体系（沿用用户后续提供的准则清单）。
