## What to build

P3 的整个优化闭环要最小化"质量"、满足"MS ≥ 0"约束，但**目前全平台没有任何地方计算质量**
（`mass` 只出现在显式动力学的质量缩放里，与结构质量无关）。本票先把目标与约束口径做出来，
否则后面所有票都在优化一个不存在的量。

新建 `core/objectives.py`（纯算法、零第三方依赖）：

- **质量计算**：按自然格蒙皮面积 × 层合板总厚 × 材料密度求和。
  物理尺度必须取自 `TopologyModel.extents()`（`y` 已是物理长度；`xi` 要乘 `xi_scale`），
  **不得把参数空间的 0..1 当米**。
- **质量口径声明**：结果里必须带 `components`（如 `["skin"]`），明确这一坨质量包含了哪些部件。
  平台目前没有加筋截面定义，所以默认只算蒙皮；加筋质量作为**可选**附加项，
  按模板声明的截面假设折算，声明了才计入且如实列出。
- **约束提取**：从一次运行的校核结果（`check.summary` 的 `max_fi` / `min_ms` /
  `all_pass`，以及 `n_bays_excluded`）提取约束状态。约束口径必须**复用**既有强度校核结果，
  不允许另起一套判定。
- **评估结果归一**：把一次运行结果整理成统一的评估结果结构，并且
  **必须把"技术故障"与"设计不满足约束"分开**：
  - 求解失败 / 网格破戒(ADR-0010) / 参数越界 → `ok=False` + `error`（技术故障）
  - 跑通但 MS<0 → `ok=True` + `feasible=False`（设计不可行）
  若混为一谈，优化器会把故障读成"设计很差"，进而错误地避开某些区域。

## Acceptance criteria

- [ ] 给定已知几何与铺层，质量可手算对照（单测断言数值正确，含容差）
- [ ] 质量使用物理尺度换算，不把参数空间 0..1 当物理长度（构造 `xi_scale ≠ 1` 的用例断言）
- [ ] 质量结果自带 `components` 声明，且与实际计入项一致
- [ ] 未声明加筋假设时只算蒙皮，并明确标注；声明后才计入加筋
- [ ] 约束口径复用既有强度校核结果（`max_fi` / `min_ms` / `all_pass`），不另起判定
- [ ] **技术故障与设计不可行在数据结构上可区分**（两者的 `ok` / `error` / `feasible` 组合不同）
- [ ] 纯算法模块，不依赖 CATIA/Abaqus/DB，可独立单测
- [ ] Python 3.8 兼容（用 `core/compat_py38.py`）
