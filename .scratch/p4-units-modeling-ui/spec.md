Status: ready-for-agent
Type: spec
Created: 2026-10-24

> 术语一律使用 `GLOSSARY.md` 定义（自然格、参数化数模、层合板/铺层、失效指数 FI、安全裕度 MS、强度校核、危险部位、可追溯性、分析任务 Study、参数集、结构拓扑模型、血缘、参数契约、参数化包络、设计点、优化会话）。本 spec 新增的术语（**单位制**、**量纲自洽**、**规格树**、**模型树**、**图形区**、**上下文栏**、**参数化模型**）需同步补进 `GLOSSARY.md`。

## Problem Statement

平台已经能跑通"参数 → 建模 → CAE → 抽取 → 校核 → 报告 → 优化 → 审批"，但有三个问题让它在真实工程师手里**不敢用**、也**不好用**：

1. **量纲不自洽，这是硬伤。** 生成的 `.inp` 里节点坐标按**米**写、壳厚按**毫米**写、模量用 **MPa**，密度又是 **kg/m³** —— 四套基准混在一个模型里。无论按哪套解释都错：按 mm 理解则弦长 1 mm；按 m 理解则蒙皮厚 10 cm、模量 135 kPa。于是 **FI/MS 的绝对数值不可信**，报告里的"最大失效指数 0.52"没有任何物理意义。更糟的是 `extract.py` 的 manifest 还声称单位制是 mm-N-MPa。这个问题从 P1 起就存在，只是**从来没有任何测试断言过量纲**（已在 #29 登记）。同时，软件里也没有任何地方让用户切换单位——模板参数写死 `"unit": "m"`，报告写死 `MPa`，质量默认按 kg 显示而内部按另一套算。
2. **参数化建模不能自己做。** 现在"建模"这一步实际上是 `catia.regenerate()` —— 而 CATIA V5 **无法**做复材参数化建模（ADR-0011 已核查：V5 任何版本的 Automation 只有 `CompositesMaterial`，没有 Ply/Stacking 对象），且本机 CATIA **无许可证**（ADR-0013）。也就是说，**平台最核心的"参数化建模"能力目前是空的**：真实环境里它一步都跑不了，只能跑 fake。而用户的诉求很明确：既然 CATIA 做不了，就让本软件自己做，做完把几何与建模信息**输出成 CATIA 能吃的格式**。
3. **界面不像工程软件。** 现在是一个 Notebook 里塞了几张页签（分析 / 审批 / 优化），左边一列参数输入、右边一个日志框。而工程师日常用的是 CATIA / Abaqus：有标题栏、菜单栏、工具栏、随上下文变化的操作栏、占据中心的图形区、左侧的树。**没有图形区就看不出模型长什么样**，只能读 JSON；**没有树就管不住对象**，找不到"这个材料属于哪个部件、载荷加在哪个分析步上"。

## Solution

把平台从"跑得通的脚本集合"升级为"量纲可信、能自己建模、像工程软件"的工作台。

- **单位制统一为 mm–N–MPa–t**（Abaqus 复材惯例），几何/厚度/模量/密度/应力/质量全部同制；**内部一律用基准单位计算与落库**，界面按用户选择的显示单位制换算——**输入、显示、写入 `.inp`、报告、质量口径、优化汇总摘要全部同步换算，不是只改标签**。提供预设单位制列表供切换（默认 mm-N-MPa）。
- **内置参数化建模**：不再依赖 CATIA 生成几何。平台自己按"模板 + 参数契约 + 参数化包络"生成**参数化模型**（蒙皮面、长桁/肋/框构件、开口、铺层定义、材料），并维护**规格树**（建模特征树）与**模型树**（CAE 对象树）。结果可导出为 **STEP / IGES**（平台自己写）与 **CATPart / CATProduct**（经 CATIA 发布步骤，需许可证；不可用时显式 SKIP，不伪造）。
- **模块化 UI**：按 CATIA / Abaqus 的成熟布局重构——标题栏、菜单栏、工具栏、上下文栏、图形区、规格树（浮动窗口）、模型树、消息区、状态栏。图形区支持线框投影的旋转/平移/缩放与热点标注；模型树图形化管理部件、材料、载荷、分析步、网格、结果。
- **量纲自洽成为可验证的性质**：新增专门的量纲自洽测试，跨边界（模板 → 参数集 → 拓扑/网格 → `.inp` → 抽取 → 校核 → 报告 → 汇总）逐一断言单位。**#29 由此关闭**，并明确历史数据的处理方式。

关键约束：**FI/MS 的计算与合格判定仍是确定性 L0**（ADR-0002/0007），单位换算不得参与任何判定逻辑；**铺层仍是 CAE 属性**（ADR-0005），参数化模型只是额外携带铺层定义用于交换。

## Implementation Decisions

### 与既有 ADR 的冲突（必须显式记录）

- **本 spec 推翻 ADR-0004**（"参数化建模采用模板 CATPart + 外部 Automation 驱动"）。理由：V5 无复材铺层 Automation（ADR-0011 已核查）、本机无许可证（ADR-0013），该路线在真实环境里不可运行。**新的真源是平台内的参数化模型**。
- **本 spec 把 ADR-0011 从主线降到备选**：既然铺层定义由平台自己生成与导出，3DEXPERIENCE 铺层自动化不再是关键路径。
- **不动** ADR-0002（AI 三层）、ADR-0005（铺层作 CAE 属性）、ADR-0007（确定性校核）、ADR-0008（自然格）、ADR-0010（网格对齐）、ADR-0012（Abaqus 侧 Py2.7）。
- 需新增两份 ADR：**单位制基准与换算**、**参数化建模内置（取代 ADR-0004）**。

### 单位制（基准 / 显示分离）

- **基准单位制固定为 mm–N–MPa–t**：长度 mm、力 N、应力/模量 MPa（N/mm²）、密度 t/mm³、质量 t、角度 deg、无量纲分数原样。**所有计算与落库都在基准单位下进行**。
- **显示单位制**是用户偏好，只影响"输入解释"与"显示格式化"，不进入计算。预设列表至少三个**自洽**的套：
  - `mm-N-MPa-t`（默认）
  - `m-N-Pa-kg`（SI 自洽）
  - `in-lbf-psi-slinch`（英制自洽；供外部供应商对接）
- 一个预设必须同时声明 length / force / stress / density / mass 五个换算因子，**不允许只改其中一个**（那正是 #29 的形态）。
- **换算只有一处权威实现**（纯算法模块），对外提供"基准 ↔ 显示"的双向换算与"带单位的格式化"。任何模块要用单位，都调它，不得自己乘除。
- **模板参数契约声明"量的种类"**（length / angle / dimensionless 等），不再只靠单位串猜。模板里写的数值按模板声明的单位书写，加载时**统一换算为基准单位**后再交给下游（拓扑/网格/FE 全部只认基准单位）。
- **参数集产物一律存基准单位**：血缘里的数字无歧义，不因查看者切了单位而变化。
- 报告、质量口径、优化汇总摘要、抽取 manifest 的 `units_note` 都必须由单位模块生成，**不允许硬编码单位串**。

### #29 的关闭与历史数据

- 新增**单位口径版本**（`units_version`）：新 Study 记 2（自洽口径），旧 Study 记为 1（历史口径）。
- 旧 Study **仍可打开、血缘仍可查**，但显式标注"旧单位口径"，其 FI/MS 标注为**不可与新结果直接比较**。**不做事后换算**——旧结果的物理意义本身就不可信，换算是伪造精度。
- 已知会变的基线：`.inp` 里的坐标从米变为毫米（弦长 ×1000）、密度从 kg/m³ 变 t/mm³、真机算出的 FI/MS 数值会变（因为之前几何与厚度不同制）。
- 每处改动的测试断言都要在提交信息里写明**原值 → 新值 → 为什么**，不允许"改到绿为止"。

### 参数化建模（内置，复用既有切口）

- **复用 `CatiaDriver.regenerate(parameter_set, template)` 这个既有协议与调用点**，不新增编排入口：提供"平台内建模"的实现，返回的数模产物结构与原来一致（路径 + 指纹 + 参数），`run_study` 一行不改。CATIA 侧的实现保留用于"发布 CATPart/CATProduct"。
- 新增纯算法模块负责**参数化模型**：由模板 + 基准单位参数集 + 结构拓扑模型生成一个**中性的几何/特征表示**（点/线/面/体的最小集合 + 特征层级 + 属性），不依赖任何 CAD 内核。
  - 几何必须能表达两类布局（翼面类长桁×肋、筒段类桁条×框）与开口，复用既有结构拓扑模型作为骨架来源，**不重复发明拓扑**。
  - 模型自带**铺层定义与材料**（作为属性，不生成铺层几何；ADR-0005 不变）。
  - **确定性**：同参数集两次生成逐字节一致（稳定 ID、稳定排序、固定精度）。
- **几何写入器可插拔**（协议 + 实现）：
  - STEP / IGES：平台自己写（纯文本生成，无第三方依赖）。
  - CATPart / CATProduct：**平台不写二进制原生格式**（那是 DS 私有格式，没有内核写不出合法文件）。改为**CATIA 发布步骤**：用 V5 Automation 打开我们导出的中性几何 → 另存为 CATPart → 组装为 CATProduct。**CATIA 不可用时明确报告"不产出该格式"及原因，绝不生成占位文件冒充成功**（现有的 fake 驱动只在测试里用，必须与真实交付物区分开）。
- **建模信息 sidecar**：中性几何装不下的信息（材料、铺层、参数集、特征树摘要、单位制）写成同名 sidecar 文件，随几何一起交付给 CATIA。
- 既有 `data/templates/*.json` 的参数契约保留，只是补"量的种类"与单位声明。

### UI 模块化

- 界面按 CATIA / Abaqus 的成熟布局组织，**布局约定写成代码里的声明式配置**（不用构建期去抓这两个软件的界面——CATIA 无许可证、Abaqus GUI 无法稳定自动化；抄的是公认布局惯例，不是像素级复刻）。
- 组成：标题栏、菜单栏、工具栏、**上下文栏**、**图形区**、**规格树**（浮动窗口，属参数化建模模块）、**模型树**（CAE 模块，管理部件/材料/载荷/边界/分析步/网格/结果/报告）、消息区、状态栏。
- **部件与材料在模型树里继承参数化建模结果**（单向引用，不复制数据）；树里改不了几何，只能查看与触发动作。
- 图形区用 Canvas 做线框投影（旋转/平移/缩放/复位），投影数学是纯算法、可单测；热点与自然格着色复用既有结果数据。
- **UI 仍不含逻辑**：所有查询与动作经服务层；UI 只绑定与显示（沿用 P2/P3 已验证的分工）。
- 既有分析/审批/优化功能全部保留在新布局内。

### 分三期实施（本 spec 内的排序）

1. **单位制**：换算模块 + 模板量纲种类 + `.inp`/报告/manifest/质量口径全链路换算 + `units_version` + 量纲自洽测试。**必须先做**：后续所有显示与 UI 都依赖它，且它决定基线数字。
2. **参数化建模内置**：参数化模型 + 写入器（STEP/IGES）+ CATIA 发布适配器 + sidecar。依赖 1（几何必须按基准单位生成）。
3. **模块化 UI**：外壳 + 树 + 图形区 + 单位切换按钮 + 既有功能迁入。依赖 1、2（要有模型和单位可显示）。

### 数据库

- 只新增：`studies.units_version`（整数）、单位显示偏好（用户/会话级配置）。走既有幂等迁移，不改既有结构。

## Testing Decisions

**好的测试只验证外部可观察行为**：给定输入（参数集、显示单位、模板），断言输出（生成的 `.inp` 数值、报告文字、导出文件内容、树结构、显示值），不断言内部调用顺序。

沿用既有先例（`apps/workbench/tests/test_m*.py`：纯标准库、临时库、`main() -> int`、由 `run_tests.py` 调度、`compat_py38` 检查 3.8 兼容）。

- **单位换算是纯算法**：直接单测双向换算与格式化；**同一物理量的往返换算必须回到原值**；每个预设必须五个量齐全（缺一个就报错）；故意构造"只改一部分单位"的错误预设，断言被拒。
- **量纲自洽测试（新增，专治 #29）**：跨边界逐段断言——
  - 参数集落库是基准单位；
  - `.inp` 的节点坐标、壳厚、模量、密度**四者同制**（用可观测的物理关系验证，例如"展长 12 m ⇒ 节点最大 Y = 12000"、"密度 1600 kg/m³ ⇒ 1.6e-9"）；
  - 抽取 manifest 的 `units_note` 与基准一致；
  - 报告里每个物理量带单位；质量带口径；
  - 换显示单位后**同一 Study 的物理值不变**（只变显示）。
- **参数化模型**：确定性（两次生成逐字节一致）；两类布局都能生成且特征树结构与参数一致；开口被表达；铺层/材料属性随模型带出。
- **几何写入器**：STEP/IGES 产物可被**独立解析器**读回关键实体（不是"文件非空"就算过）；sidecar 含材料/铺层/参数/单位制。
- **CATIA 发布**：不可用时显式 `unavailable` + 原因，**断言没有产出 CATPart 文件**（防止假成功）。
- **UI**：逻辑走服务层单测；UI 冒烟构造并销毁（无显示环境 SKIP）；图形区投影数学单测；单位切换按钮走服务层断言。
- **回归基线**：P1–P3 的既有测试如因单位自洽而数值变化，逐条记录原值/新值/理由；**不允许放宽断言到失去意义**（例如把"弦长 1.26 m"改成"弦长 > 0"）。
- **Abaqus 侧脚本**：继续通过 `compat_check`（Python 2.7 基线）。
- **真机**：探测到 Abaqus 则跑；CATIA 依 ADR-0013 现状跳过并显式 SKIP。

## Out of Scope

- 自研几何内核（B-rep 布尔、NURBS 曲面求交等）：本期只生成"够 CAE 与交换用"的结构化几何，不做通用 CAD 建模器。
- 原生写 CATPart / CATProduct 二进制（DS 私有格式，必须有 CATIA 内核；本期经 CATIA 发布步骤获得）。
- 3DEXPERIENCE 铺层自动化（ADR-0011 降为备选）。
- Web 协作端（Win7 上不建，ADR-0001 已有结论）。
- 真正的网格自适应与 AI 质量门（P3 已完成的部分不重做）。
- 单位制的自由文本自定义（只提供预设列表；自由单位会让"自洽"无法保证）。
- 图形区的 photorealism / 有限元云图渲染（只做线框投影 + 自然格着色 + 热点标注）。
- 把参数化模型反写回 CATIA 模板（几何单向流出）。
