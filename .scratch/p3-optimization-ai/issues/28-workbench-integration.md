## What to build

把优化结果接到工作台（服务层 + UI），让项目负责人能在一个视图里看清整次优化。

沿用 P2 已验证的模式（票08/票19）：**UI 控件难以自动化测试，所以所有逻辑放服务层**
（纯 Python 可单测），UI 只负责调它 + 显示。

服务层（`workbench_service`，纯追加）：
- 列出优化会话；取某会话的汇总（各设计点目标值/约束/可行性/是否最优，按三类分组）
- 取某设计点的完整血缘（用于点开查看"这个数是怎么来的"）
- 优化前后对比（质量降低多少、最小 MS 变化多少）
- 采用方案（走 L2 批准）与「维持原设计」的入口

UI（`ui_workbench`）：
- 新增「优化」区域/标签页，展示会话列表与汇总视图
- 设计点可点开看血缘
- 采用/维持原设计的操作按角色门控（**未批准不可采用**）
- 保持既有「分析」页与「审批与型号汇总」页功能不破坏

## Acceptance criteria

- [ ] 工作台可展示优化会话列表与汇总视图（**测服务层**）
- [ ] 汇总按「可行 / 不可行 / 评估失败」分组，能区分技术故障与设计不可行
- [ ] 设计点可点开查完整血缘
- [ ] 优化前后对比数值正确（质量变化、最小 MS 变化）
- [ ] 采用方案入口**只对已批准 **；未批准一律拒绝（服务层断言 + UI 置灰）
- [ ] 「维持原设计」可操作且被记录
- [ ] 工作台逻辑在服务层，可脱离 UI 单测（除 UI 冒烟外不 import tkinter）
- [ ] UI 冒烟可构造并销毁；无显示环境则 SKIP
- [ ] 既有「分析」页与「审批与型号汇总」页零回归
- [ ] Python 3.8 兼容
